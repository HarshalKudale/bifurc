## What moved

28 files: `src/proxy/` (19), `src/sync/` (8), `src/eventBus.ts` (1).

**They had to move together, and the plan's ordering was wrong.** `plan/03` listed `eventBus.ts`
*after* `proxy/` and `sync/`, but `eventBus.ts` imports `@/proxy/logEmitter`, `@/proxy/webhookServer`

Measured the coupling before starting rather than trusting the doc.

## Rewrite: 189 statements across 95 files, in five passes

Layer 1's two passes were not enough. Two new classes of rewrite, both silent-failure traps:

- **Pass 4 — `@bifurc/engine/*` self-imports inside the package must become relative.** After layer
  1 the moved files already contained 23 such imports. They *appear* to work, but resolve through
  the `exports` map to `dist/` at runtime while the rest of the engine loads from source — two live
  copies of module state, exactly the silent-singleton failure `bundle: false` exists to prevent.
- **Pass 5 — `vi.mock()`.** An import-shaped regex (`from "…"` / `import(` / `require(`) does not
  match `vi.mock("@/sync/autoSync", …)`; it is a plain call. The first four passes rewrote 177
  specifiers and still left **12 stale mock specifiers across 7 files**. A mock whose specifier no
  longer matches its subject is worse than no mock — the real module loads and the test silently
  stops being hermetic. Guarded to skip `tests/renderer/**`, whose `@/lib/*`, `@/hooks/*` and
  `@/components/*` mocks belong to the renderer's own alias space.

## Two grep false positives, resolved differently

- `eventBus.ts`'s doc comment quoted `BrowserWindow.getAllWindows()` → **reworded** (keep the
  information, drop the token), matching what layer 1 did for the store comments.
- `proxy/service-discovery.ts` holds a literal Windows path ending in `powershell.exe`, which the
  unanchored pattern `shell\.` matched → **refined the criterion to `\bshell\.`** rather than
  mangling working code. The word-boundary form is the correct semantic (Electron's `shell` API is
  always a standalone identifier) and still catches `shell.openExternal(url)` in
  `src/ipc/handlers/clientHandlers.ts`. Plan doc updated.

## New finding — packaging does not follow the package split

`build.files` is `["dist/**/*","package.json"]`. electron-builder **does** add production deps'
`node_modules`, but it does not dereference the `node_modules/@bifurc/*` workspace symlinks — the
last real asar (`release/win-unpacked/resources/app.asar`, built 2026-09-10) has **no
`node_modules/@bifurc`**. Meanwhile the current `dist/` requires `@bifurc/protocol`
(`dist/commands/registry.js`, since item 7) and `@bifurc/engine` (20+ files, since items 7–8).

So a **packaged** build cannot resolve either specifier. Dev mode and the whole test suite are
unaffected (the symlink resolves locally). Stated precisely: the 09-10 asar predates both
dependencies, so it cannot demonstrate the failure directly — it confirms only what gets copied.
Confirming end-to-end needs one `electron-builder --dir` run.

**Not fixed here** — `plan/12` already owns this ("Change point 1 — at P6"), and P6 replaces the
mechanism with an `extraResources` binary anyway. Recorded in `plan/12` with the evidence, in
`plan/13` as an open item, in `plan/03`, and in `MEMORY.md`.

### Found: a `coverage.exclude` entry that was wrong all along

`src/applications/types.ts` was listed under "Type-only modules". It is not type-only — it exports
`DEFAULT_DEBUG_PORTS`, `RUN_CONFIG_TYPE_LABELS` and `RUN_CONFIG_TYPE_ICONS` as real runtime values.
The exclusion was made on the strength of the filename and had been hiding live, fully-covered code
from the report the whole time.

Rather than carry a wrong exclusion to its new path, the entry was **removed**. The file now reports
3/3 lines at 100%, which is why the denominator grew by exactly 3 statements (11,443 → 11,446) and
the numerator by exactly 3 — a scope change that is entirely explained and entirely an improvement.

This is the mirror image of the layer-1/2 problem (a stale exclude that silently stops matching).
The lesson recorded in the skill: never relocate an exclude entry without checking the file really
is type-only (`grep -nE '^export (const|function|class|let|var|enum|default)' <file>`).
