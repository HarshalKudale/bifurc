## What the migration actually was

**The headline finding: "migrate the eight suites onto `edgeRequest()`" was wrong for six of them.** Only
`mappingsAndRules` and `mocks`/`capture` needed the request seam re-pointed. For the rest the **premise** had
to be re-read against the split, and each failure named a different thing:

- **`settingsMutations` (28 → 0, 28 → 31 cases).** `bootOnConfiguredPort()` started **only the forward
  proxy** while `fetchHello()` asked a `*.localhost` host → every routing case got the deliberate 400. It now
  boots **both** listeners the way `index.ts` does (edge on `settings.port` first, proxy on a resolved port).
  Its *subject* was also superseded: *"changing the proxy port moves the live server"* is no longer true or
  wanted, because `settings.port` is the **edge's** — `config.save` keeps the proxy on its resolved port and
  a port change is a preference for the edge's next boot. **10 further cases were failing on a leftover
  `stopCompanionServer()` in `afterEach`** — a companion-removal loose end from my own earlier repair.
  The P14 WI 4 pair split into two honest halves, and the split is instructive: the **proxy** is
  pointer-inert (its config is read at `start()`), the **edge** follows the pointer (it re-reads
  `loadConfig()` per request) — and the old case read both through one port, so it could not tell them apart.
  Neither answer is a bug; reading through the wrong seam is.
- **`workspaceCommandScope` (1 → 0) — the assertion was INVERTED.** `portIsFree(configPort)` was false
  because the **host binds the edge** on `settings.port` (`host.ts:493`). The port is *correctly* occupied;
  the case now asserts the edge holds it and that no third *proxy* does.
- **`workspaceDispatchScope` (3 → 0).** Relative targets to a `*.localhost` host are refused by the forward
  half; mocks match on the **absolute** URL, so the targets became absolute-form. **And the fixture mock
  needed `mockedResponseHeaders`** — without it the mock is a *partial* overlay that still calls an upstream,
  and the cases failed **502**, measuring the upstream instead of the dispatch scope.
- **`workspaceRuntime` (1 → 0).** The home page is the edge's now, so the *liveness* probe became the forward
  proxy's own documented refusal (`status > 0`). The case's own comment had already said the home page was the
  wrong instrument for content.
- **`entityConflictScope`, `foldersAndWorkspaces`, `protocolExecution` (3 load errors → 0).** Stale
  `@/ipc/handlers/*Kinds` imports repointed at `@bifurc/engine/store/kinds/` — the **WI 10** move these three
  had been missed by. Their 69 cases were `skipped`, which is why the skip count fell 109 → 40.
- **`ipc/handlers.test.ts` (1 → 0).** Three `toHaveBeenCalledWith(<config port>)` assertions became the
  **resolved** port: `server.start` / `server.restart` / `config.save` all read `getPort()` first.

## The two missing files, written

- **`tests/proxy/edge.test.ts` (28 cases, mock-based)** — the 17 reverse-half cases moved out of
  `server.test.ts` (now the forward half, 78). Owns the routing *decisions* and the configs the filesystem
  cannot produce (null config, throwing `resolveConfig`, `EADDRINUSE`).
- **`tests/integration/edgeSplit.integration.test.ts` (18 cases, real I/O)** — the plan's own verification
  step. Owns what only sockets can show: **the same URL answering differently on the two ports** (edge `200`
  / forward `400`), the raw-bytes-to-`req.socket` handler, and `resolveConfig` per request. It **supersedes
  `harnessSplit.integration.test.ts`**, which was folded in and deleted (its own header asked for that).

**A finding worth keeping:** `resolveConfig` is a *parameter*, and the tree has two compositions that
differ — the engine facade passes `() => loadConfig()` (fresh per request), the host passes
`() => instance.dispatchConfig()` (refreshed only by `reloadConfig()`). **The assertion I wrote initially
failed for a third reason entirely** (a sibling case's `createWorkspace().cleanup()` had reset the store
override to `null`, un-pointing the store for every later case). A reader taking that first failure at face
value would have "fixed" `dispatchConfig()` to re-read per request, changing D16's semantics to satisfy a
test that was measuring the wrong workspace. Both shapes are now pinned **separately**, each saying which it
is.

## The flake, and the generalisation

A full run put three `portAllocator` cases red at once (`expected 49529 to be 49528`,
`expected 50235 to be 50234`, and a `nextFreePortAbove` miss) while all **35/35 passed isolated**. Cause: the
cases assert on an *ephemeral* base's **successors** (`base + 1`, `base + 2`), and this session's new suite
binds a facade edge plus two harness listeners, landing ephemeral ports on them. **This is the same mechanism
`allocateFromUncontendedBases`' header already records for `workspaceCommandScope` (2026-09-21)** — arriving
through a third suite. Remedy: a shared **`holdBaseWithFreeSuccessors()`** used by every successor-asserting
case, and the regression it guards **still fails** (`EXIT=1`, 6 red). Two consecutive full runs green after.

**The generalisation: adding a suite that binds ports silently degrades every "the scan lands on `base + N`"
assertion in the tree, and nothing connects the two files.** The pressure is invisible from either side.

## `plan/15` WI 5 — the GUI on the edge, built

The owner's instruction, and it corrected my first attempt: *"the web UI starts as usual on some different
server like 5753 or any other port. Our edge port reverse proxy will forward base domain requests to this web
UI port, so that this base domain → webUI port becomes the global mapping in reverse proxy config."*

**I had started building a static-file server in the edge** — `guiAssets.ts`, a `sendBytes` refactor in
`pages.ts`, MIME types, `cache-control`, a path-traversal guard, async reads. **All of it was deleted**, and
the reason is the whole point: serving the bundle would have taught a *router* about Vite's `assetsDir`
convention, cache headers and traversal, none of which belong in a module whose job is "route a Host to a
target". As a **target**, the GUI is answered by `proxyToUpstream()` — the very call branch 2 makes — so the
engine learns nothing about the GUI beyond its address, and a GUI run by nginx or `vite preview` is
indistinguishable from one this repo built. **Fewer lines, no new surface, and the property the owner wanted.**

### What landed

- **The global mapping**, checked **before** the workspace mappings (`plan/15` §3.3's new `G` row). Gate:
  `host === hostDomain` **or** `isLocalAddress(host)` — `localhost` or any IP literal.
- **`--gui-target` / `BIFURC_GUI_TARGET`**, `host:port` or a bare port meaning loopback. **No default,
  deliberately:** a plausible `5753` would forward the base domain to a dead port and answer **502** on a
  fresh install — worse than the home page, and misleading because it looks like a bug rather than an
  unconfigured feature. `undefined` → inert → the base domain falls through to the home page, which is the
  desktop's normal state and preserves today's behaviour exactly.
- **`hostnameOf()`** in `serverUtils.ts` fixes a bug both listeners had: `split(":")[0]` yields `"["` for
  `Host: [::1]:80`. Harmless as a log label, **not** harmless once `G` routes on it.

### Two consequences I had to decide, and one I had to correct in the plan

- **A workspace mapping on the engine's own hostname is now silently dead.** The global mapping wins. That
  makes §3.3's **write-time collision refusal unnecessary for its stated reason** (*"which would shadow the
  GUI and make the admin surface unreachable"*) — the GUI can no longer be shadowed. Still a possible
  *courtesy*; not a correctness gap. Flagged to the owner rather than silently dropped.
- **§3.3 row 4's *"and the path is not `/`"* clause is dropped** — incoherent for a bundle whose entry point
  **is** `/` and whose assets resolve relative to the document (`base: "./"`).
- **`plan/15` §3.3's table was the spec and I changed the design, so the table was updated rather than left
  to disagree with the code.** Rows 3/4 became `G`; the divergence is written up where the table is.

# `--domain` removed — the engine is no longer deployable in the cloud (owner instruction)

**The decision, in the owner's words:** the engine will always be part of an Electron application or a locally
deployed Docker image — a **per-user instance**, which is what the future admin console and login flow need —
so the base domain is always `localhost`. Subdomains stay the reverse-proxy mappings; the reverse-proxy port
stays host-level and shared across workspaces; the mappings table stays the active workspace's. *"This is
really a basic change."*

## What deliberately did NOT change, and why

- **The three bind opt-ins.** They publish a *port* to a LAN, which a locally deployed image still needs; they
  were never about a domain.
- **`hello`'s `hostDomain`.** Still on the wire, now always `localhost`; `plan/16`'s relay reads it, and §4.1's
  *"the host decides, the client does not guess"* is unchanged. Its **transport option stays optional**, so
  `auth.test.ts`'s two cases still mean something.
- **`EdgeRouterOptions.hostDomain`.** An internal parameter, like `bindHost` — the *deployment* knob is what
  went.
- **`normalizeHostname`.** Its only production reader is now the edge's own-name gate.
