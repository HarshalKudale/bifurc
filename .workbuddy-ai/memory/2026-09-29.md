## The test migration — the subtle part

`tests/ipc/handlers.test.ts` mocks **only** the seam's *reload* half:

```ts
vi.mock("@bifurc/engine/runtime/instances", async (importOriginal) => ({
  ...(await importOriginal<typeof import("@bifurc/engine/runtime/instances")>()),
  notifyConfigChanged: vi.fn(),
}));
```

`rebindRuntimePorts` is **left real** so the port assertions (`restartEdge`/`startServer`/`startWebhookServer`)
still observe real calls against the listener mocks. Stubbing both halves would have made those assertions
vacuous — they'd watch a stub call nothing. The `reloadConfig` assertions (`workspace.setActive`, `env.setActive`)
move to `notifyConfigChanged`. `importOriginal` spread is required: a whole-module replacement makes
`rebindRuntimePorts` `undefined` → `TypeError` inside the command.

`tests/integration/facadeBinding.integration.test.ts` **keeps** importing `reloadConfig` directly — it tests
the proxy's *own* surface, not the fan-out. `tests/integration/entityConflictScope.integration.test.ts` mocks
`proxy/server`'s `reloadConfig` as a bare `vi.fn()` and never asserts on it; the new chain still lands on that
mock, so no change needed.

## ⚠ THE BIG FINDING — the codemod has a SIXTH blind spot, and it was a real failure

The applied-phase acceptance test is "re-running must report 0". It did report 0 rewrites / 0 files. But the
integration suite **failed**: `Cannot find package '@bifurc/engine/store/configCommands'` at
`tests/integration/workspaceHost.integration.test.ts:622`.

Cause: that file has a **`Record<string, string>` table of module paths** passed to
`await import(/* @vite-ignore */ specifier)` — a **variable**, not a literal. No codemod can resolve it, and
`@vite-ignore` stops Vite resolving it at build time too. Five rows were stale
(`Config`, `Audit`, `Core`, `Folder`, `EntityCrud`).

**Why it surfaced and why that matters:** the test asserts
`expect(mod, "the shell calls register${fn}Commands() but no such export was importable").toBeTypeOf("function")`
— i.e. the guard is *designed* to catch exactly this, and it did. `Config` and `Audit` are rows for call sites
the shell does not currently make, so they were never loaded — but `Core`/`Folder`/`EntityCrud` are real, so the
test blew up on the first one. **The lesson is that a `toBeTypeOf` guard on a dynamic import converts a silent
stale-string into a loud failure** — worth keeping that shape wherever a path table is unavoidable.

Fixed by hand (5 specifiers + the docblock example + a new ⚠ paragraph naming the blind spot, so phase 4–7 does
not rediscover it). Verified: `npx vitest run --project integration tests/integration/workspaceHost… -t registerAll`
→ **1 passed**.

## P19 WI 3 — the engine half of the pipeline

**`packages/engine/src/pipeline/runPipeline.ts`** — D24's one function, `resolve → pre-script → send →
post-script → test`, with **`send` injected** so the file knows no protocol. Everything else (which
environment, what the pre-script may rewrite, what the post/test scripts see, how the body crosses the
text/base64 boundary) lives there once. A protocol whose payload the generic `PipelineRequest` shape cannot

not a second resolver.

**`packages/engine/src/workspace/envState.ts`** (new) — `loadMergedEnvironment(wsId)`: `__global__` as base,

here now *because* `pipeline/` is the call. Same semantics as `App.tsx:288` (global first, active second,
so active wins a collision).

reachable (the desktop's `loadConfig()` auto-creates `__global__`), preserved because changing it inside a
move is a behaviour change smuggled in under a refactor. There is a test asserting the current behaviour, so
"fixing" it is now a deliberate change.

to the active value while a global-only key stays reachable (mutation-verified: dropping the merge in
