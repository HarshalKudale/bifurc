## Session 2 — P2 item 8, layer 1: `packages/engine` created, bottom layer moved

Item 8 is the physical `packages/*` restructuring. Done in layers rather than one commit, per the
phase doc's own mitigation ("do one package first, prove the pattern, then move the rest"). This
session did **layer 1** — the bottom of the dependency graph.

### What moved

`git mv src/{store,lib,subscription}` → `packages/engine/src/` — 14 files, blame preserved.

### The package

- `packages/engine/{package.json,tsconfig.json,tsup.config.ts}` + a provisional `src/index.ts`.
- `dependencies: {"simple-git": "^3.36.0"}` — the entire runtime surface of the moved layer. No
  Electron, no renderer, no React. `devDependencies`: `@types/node`, `tsup`, `typescript`.
- Multi-entry, structure-preserving build: `dist/store/config.js` (CJS) + `.mjs` (ESM) + `.d.ts`.
  No `"type": "module"`, so `.js` is CJS — which is what the Electron main process requires.

### `bundle: false` is load-bearing, not a style choice

`store/paths.ts` holds the resolved data root as module-level state; `store/config.ts` and
`store/gitStore.ts` hold caches the same way. With a bundling build each entry gets a **private
copy**, so `setDataRoot()` through one entry stops affecting the modules reached through another —
and because the failure mode is a fallback rather than a throw, it is silent. Verified after the
build: `dist/store/config.js` does `require("./appSettings")` / `require("./workspaceFs")`, and
`dist/store/paths.js` owns the singleton.

### Three resolution paths (all deliberate)

| Consumer | Mechanism | Target |
|---|---|---|
| `tsc` | root `tsconfig.json` `paths` | `packages/engine/dist/*.d.ts` |
| vitest | new `engineAliasPlugin` | `packages/engine/src/*.ts` (source) |
| Node runtime | package `exports` map | `packages/engine/dist/*.js` |

Tests point at **source** so they exercise real code and `coverage.include` can instrument it —
resolving to `dist` would have reported the engine as 0% covered while testing compiled JS.

### `tsc-alias` behaviour — verified, not assumed

It rewrites `@/*` to relative paths (`@/sync/syncManager` → `./sync/syncManager`) but leaves
`@bifurc/engine/*` and `@bifurc/protocol` **bare**; Node resolves those through the workspace
symlink + `exports` map. This made an initial `build.files` addition unnecessary, so it was
reverted — adding manifest entries that do nothing is worse than adding none.

### Import rewrite

**254 statements across 97 files** → `@bifurc/engine/*`. `renderer/`: **0** — its `@/` alias points
at `renderer/`, so it never referenced the moved layer. Done in two passes because the first missed
a whole category:

1. `@/store/*`, `@/subscription/*`, `@/lib/{randomNames,randomizer}` → 170 statements / 90 files.
2. **Relative** imports into the moved dirs (`../../src/store/gitStore`) → 84 statements / 7 files,
   all in `tests/` (`src/` used the alias consistently). The second pass resolves each specifier
   against its file's directory rather than pattern-matching `../..`, so it catches any depth.

The engine is now **alias-free internally** — its 7 `@/store/*` imports became relative.

### Latent CI bug found and fixed

`dist/` is gitignored repo-wide, so neither package's build output is committed, and CI only ran
`npm ci`. A fresh clone therefore failed `npm run typecheck` with **10× `TS2307: Cannot find module
'@bifurc/protocol'`**. Adding a second package would have doubled it. Fixed with `build:packages`
wired into `prepare` (which `npm ci` runs), plus `build:main` and `typecheck`.

### Cleanup in passing

Deleted two `vi.mock("@/subscription/gate")` blocks (`tests/ipc/handlers.test.ts`,
`tests/spike/protocolPoc.test.ts`). They mocked a module that has never existed in this repo's
history (`git log --all` shows no such file) and exposed an older `canCreate`/`canEnable` API while
the real `subscription/entityCount.ts` exports `gateCreate`/`gateEnable`. Inert, but they would have
produced a bogus `@bifurc/engine/subscription/gate` specifier during the rewrite.

Also reworded three comments in `store/{paths,appSettings,workspaceFs}.ts` that quoted
`app.getPath("userData")` while explaining what the shell does. The acceptance criterion is a literal
`grep … returns zero`; keeping three known false positives would make a future real violation easy to
miss. Information preserved, token removed. Fixed two stale `src/store/...` comment references too.

## Session 3 — the engine test-resolution bug, and proof the move is safe

The open thread from Session 2 was that the engine reported **all 14 files at 0%** coverage while the
suite passed 1615/1616. Resolved.

### Root cause

`@bifurc/engine` is a genuine npm workspace package, so Vitest classified it as **external** and
loaded the built `packages/engine/dist/*.mjs` through native `import()`. Three candidate fixes were
tried; only one works:

| Mechanism | Result |
|---|---|
| `resolveId` plugin (as `dualAliasPlugin` does for `@/`) | **Never invoked** — externalization precedes plugin resolvers |
| `deps.inline: [/^@bifurc\/engine(\/|$)/]` (and legacy `server.deps.inline`) | **No effect**; not needed at all |
| `resolve.alias` | **Works** — but only when redeclared inside each `test.projects` entry |

The last caveat was the expensive part. **Root-level `resolve.alias` (like root-level `plugins`) is
silently not inherited by project runs** — which is precisely why `plugins` had always been
duplicated into each project, and why `dualAliasPlugin` worked while the engine alias did nothing.
Proven by corrupting the alias target to a non-existent `packages/engine/src/__BOGUS__/` directory
and observing the suite still pass against `dist/`. Fixed by sharing one `viteOptions` object
(`{ plugins, resolve: { alias } }`) across the root and both projects.

Why this mattered more than the coverage number: while it was broken, **a source edit that was never
rebuilt was silently untested**. The suite was green against stale compiled output.

### Verification that the extraction is behaviour-preserving

- Full suite **1615/1616 over 69 files** — identical to baseline; the 1 failure is the documented
  sandbox `ECONNREFUSED 127.0.0.1:1` in `tests/spike/protocolPoc.test.ts`.
- Per-file coverage vs `coverage-baseline/`: **11 of the 12 comparable moved files are identical on
  all four metrics including raw covered/total counts.** `store/config.ts` has identical totals
  (138/134/55) with a *higher* numerator — P2 items 5–7 added tests reaching more of it. Identical
  denominators prove no statement was added, removed or restructured.
- Headline coverage **47.96 / 31.98 / 36.30 / 50.35** (was 46.14 / 31.30 / 34.34 / 48.39) against a
  denominator that *grew* 11,129 → 11,443 statements — a real gain, not a scope artefact.
- Unit 52 files / 1284 tests; integration 17 files / 332 tests (sums to 69 / 1616).
- The only 0% file is the new `packages/engine/src/index.ts` barrel, deliberately left in the report
  — it becomes the real API when `createEngine()` lands.

### Incidental findings

- **`packages/protocol/src/**` appears in coverage it was never included for** — a sourcemap
  artefact: `dist/index.js` is executed via the `exports` map and V8 remaps it back through
  `dist/index.js.map`, whose `sources` list `../src/commands/*.ts`. Harmless (~100%), but it inflates
  the denominator.
- **`coverage.include` needs an explicit `packages/engine/src/**/*.ts`** — `src/**/*.ts` does not
  match `packages/*/src/**` (verified against the glob engine Vitest uses). Without it the moved
  files vanish from the report.
- **Sandbox trap:** `build:packages` / `typecheck` / `build:main` fail once a turn has accumulated
  ~50+ deletions, because the guard blocks `tsup`'s `bundle-require` from unlinking its temp
  `tsup.config.bundled_*.mjs`. Not a code bug — passes with the sandbox bypassed.
