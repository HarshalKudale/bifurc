### Item 6 remainder — workspace bootstrap extracted (`src/startup.ts`)

`bootstrapWorkspaces(settings)` now does what `main.ts`'s `app.whenReady()` did inline: init every
known workspace's dirs + git repo, start auto-sync where `syncConfig.autoSync` is set, then repair
`activeWorkspaceId` or create a default workspace — plus the engine-internal
`setAutoSyncReloadFn(reloadConfig)` wiring. `main.ts` is now one call and no longer imports
`workspaceFs` / `gitStore` / `autoSync` / `syncManager` / `store-config`. It returns the effective
settings rather than mutating the caller's object.

**Preserved quirk, documented in the source:** the loop calls `initWorkspaceDir()` for every
*listed* workspace, so the "is the active workspace's dir on disk?" check can never fail for one —
the fallback/create branch only fires when `activeWorkspaceId` is absent from `workspaces`.
Pre-existing behaviour, preserved verbatim because P2 is an extraction, not a behaviour change.

### Item 3 remainder — idempotent shutdown (`src/shutdown.ts`)

Memoised `shutdownEngine()` (spawner → pollers → companion → proxy; children before servers) plus
`isShuttingDown()`. `processSpawner.stop()` gained a per-entry `stopping` guard so `stopAll()` is
repeatable and a late stop cannot flip an exited process back to `"stopping"`. Entries stay in the
map so `getState()` / `getLogs()` survive shutdown. `main.ts`'s `before-quit` is now one call.
