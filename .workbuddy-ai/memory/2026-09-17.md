## What landed

**All 34 exporter/importer files take and return content.** `filePath` is gone from the interface,
from the registry, and from `@bifurc/protocol`.

```ts
interface ExporterFn { run(wsId: string): Promise<ExportResult> }
// ExportResult = { ok: true; content: string; suggestedName: string } | { ok: false; error: string }

interface ImporterFn {
  preflight(wsId: string, source: ImportSource): PreflightResult          // sync
  run(wsId: string, source: ImportSource, strategy: CollisionStrategy): Promise<ImportResult>
}
// ImportSource = { content: string; filename: string }
```

Both result unions are discriminated on `ok`. The old shape made every field optional, so `{ ok: true }`
alone type-checked.

**`filename` is not decoration** — two importers genuinely need it and both used to derive it from a
path: `environments-dotenv` names the new environment after it, `requests-openapi` picks YAML vs JSON
by its extension.

**`workspace-zip` (both directions) keeps a path-based signature**, behind separate `PathExporterFn` /
`PathImporterFn` registry slots. Not taste: `archiver` pipes to a `WriteStream` and
`unzipper.Open.file()` rejects a buffer outright. Separate slots rather than a `LegacyImporter` adapter
keeps "the importer interface takes content" true everywhere else **and** makes the
`workspace-zip`-last ordering enforceable.

**`src/ipc/importExportHandlers.ts` is the client half.** It shows the dialog first, calls
`export.create`, then either decodes inline bytes or pulls the blob with the `blob.read` chunk loop,
then writes the file itself. The renderer keeps sending `filePath` because it cannot change before P7;
the shell bridges it to a `blobId` in `pendingUploads`, so the **wire** is blob-shaped while
`window.api` stays byte-identical. That is how item 7 and `README.md` non-negotiable #3 were
reconciled — in favour of the non-negotiable.

## Three production bugs, all invisible to the old suite

### 1. `workspace-zip` export threw on every call

`import archiver from "archiver"` + `archiver("zip", …)` is the **v5–v7** API. `archiver` 8 is pure
ESM (`"type": "module"`, `"exports": "./index.js"`) with **no default export**, so
`require("archiver").default` is `undefined` and every ZIP export threw
`TypeError: archiver is not a function`.

Nothing caught it: `@types/archiver` was pinned at **7**, which declares `export = archiver` (a
callable default) and therefore *describes the old API*, so `tsc` was satisfied — and no test had ever
executed the exporter.

**Fixed as a pair:** `import { ZipArchive } from "archiver"` + `new ZipArchive({ zlib: { level: 6 } })`
**and** `@types/archiver` `^7.0.0` → `^8.0.0`. Fixing only the import leaves the compiler endorsing a
call shape the runtime rejects.

> **The asymmetry that hid it:** `packages/engine/tsconfig.json` uses `moduleResolution: "bundler"`
> (prefers `@types/archiver`'s ESM `types@esm`, which has no default export) while the root
> `tsconfig.json` uses `"node"` (prefers the CJS `export = archiver`, which *does* look callable).
> Version 8 has neither default, so both resolutions now agree.

### 2. A YAML OpenAPI spec was previewed with a fabricated count

`importers/requests-openapi.ts` had **two parsers**. `run()` used `loadSpec()` (JSON vs YAML, parsed
properly); `preflight()` tried `JSON.parse` and on failure returned
`Math.floor(lines containing ":" / 3)` as `itemCount`. So a YAML spec's count was fiction, **and any
text that failed `JSON.parse` came back `ok: true`** — a malformed file was offered to the user as
importable.

`loadSpec()` was `async` (it used `await import("js-yaml")`) and `preflight` is a **synchronous**
method on `ImporterFn`, which is exactly how they drifted apart.

**Fixed** with a static `js-yaml` import, a synchronous `loadSpec()`, and one parser serving both
halves — which is what `ImporterFn`'s contract already claimed.

### 3. `environments-dotenv` named the environment `""` for a file called exactly `.env`

`filename.replace(/\.env.*$/, "")` strips to the empty string. The `|| "Imported"` fallback was in the
plan's own snippet but not in the code. Latent fix; not a new `TESTING.md` row because the plan had
already flagged the name-derivation site.

### Plus one protocol defect

`ImportCommitParams.collisionStrategy` was frozen as `["skip","overwrite","rename"]` while every real
call site uses `["keep","override","new"]`. As written, `import.commit` would have rejected **every**
real import. Corrected in `packages/protocol/src/commands/export.ts`; both the acceptance of the three
real names and the rejection of the three retired ones are asserted.

## A path-derivation site the plan's own grep misses

`plan/04` says to grep for `filePath.split` / `path.basename(filePath)`. That finds
`environments-dotenv` and **misses `importers/requests-openapi.ts`**, which used `path.extname(filePath)`
— and that one is worse: a staged blob's content file is named `content` and has **no extension at
all**, so under the blob layer every YAML spec would have silently taken the JSON branch.

**Lesson:** when auditing "no path leaks", grep for path *consumers* (`path.extname`, `path.dirname`,
`readFileSync(filePath)`), not just the two the plan happened to name.

## Environment gotcha found (new — worth keeping)

**Do not scan `tsup`'s `.d.ts` output for "dangling chunk references" with a naive resolver.** I burned
time on a phantom "11 dangling chunks" alarm (which then "became" 126 on a second scan) after an
interrupted build. tsup's `.d.ts` files reference `./chunk-XXXX.js` while the file on disk is
`chunk-XXXX.d.ts` — TypeScript substitutes `.d.ts` for `.js`. **Strip the `.js`/`.mjs` suffix before
probing for `.d.ts`/`.d.mts`.** Done correctly the answer was **0 dangling on both graphs** (250 dts
refs, 497 js runtime refs). The interrupted build was the sandbox safe-delete trap, not a code defect:
`npm run typecheck` (= `build:packages && typecheck:packages && tsc --noEmit`) is EXIT=0 and proves the
whole chain.

Also: `archiver@8` ships **no** types (`types: null`, `exports: "./index.js"`), so `@types/archiver` is
genuinely required. It is declared in the root **`dependencies`** block, not `devDependencies` — I
briefly mistook it for missing by probing the wrong section.

## Two defects found — both the same class, and both invisible to the old suite

1. **`RunReport` was narrower than its only caller.** It was typed from the *HTML renderer's field
   usage* rather than from the renderer's real `CollectionRunReport`, so `requestId`, `url`,
   `testLogs`, `preScriptError`, `postScriptError` and `TestResultEntry.durationMs` were absent.

   truncated the **JSON** export — and the HTML renderer touches only fields the schema happened to
   have, which is exactly why it would have shipped unnoticed. Same class as the `collisionStrategy`
   defect: a wire type that disagrees with its only caller, with the compiler satisfied either way.
2. **`tls.importCert` leaked an absolute engine path.** It read `blobContentPath(blobId)` directly,

   runtime string, so no grep could have found it.**

# P3 work item 5 — the certificate lifecycle (evening)

**Item 5 is done as a mechanism, and deliberately open as a UI.** Scope was set by the user's two
answers: *"Full two-sided lifecycle"* (move `installCA` into the shell **and** add `uninstallCA`) and
all three unverifiable-bits options (*implement + mock-test the command shapes*, *add a Linux fallback
chain*, *record as a P9/P12 verification task*).

## The shape of it

Two halves that live on different machines and **silently drift** (`File_Ops_Protocol.md` §6):

- **engine** — generates, stores and *identifies* the CA. New `packages/engine/src/proxy/certCommands.ts`
  (`registerCertCommands`) owns `tls.generate` / `tls.certStatus` / `tls.removeCert`. `installCA` and
  `InstallResult` are **deleted** from `certManager.ts`, per `plan/04:475`.
- **client** — installs into the OS trust store, compares, un-trusts. New `src/ipc/certTrust.ts`
  (pure platform plans + injected `TrustContext`) and `src/ipc/certLifecycle.ts` (composition: bytes +
  trust store + drift record).

`certPath`/`keyPath` leave the two result types and are replaced by a **fingerprint** — a path is
meaningless on a remote client (§8 boundary violation). The shell re-synthesises both fields from
`caCertPath()`/`caKeyPath()` for `TlsSettingsSection.tsx`, exactly as `tls:importCert` already did, so
**`window.api` stays byte-identical** and every new field is additive and read by nothing.

## Two measurements that changed the design

Both against the real `certutil` on Windows 11, and **the first one would have shipped a
security-relevant lie**:

```
certutil -delstore -user Root <sha1-of-absent-cert>   → exit 0
certutil -store    -user Root <sha1-of-absent-cert>   → exit 17 (NTE_NOT_FOUND), exit 0 when present
```

`-delstore` exits 0 whether or not it deleted anything, so **"the command succeeded" is not "the
certificate is gone"**. Consequences, all three now load-bearing:

1. `run` and `probe` are separate concepts in `TrustContext`.
2. `TrustResult.verified` is separate from `ok`, and `uninstallCA` **re-queries** the store instead of
   trusting the exit code.
3. `probeTrust()` returns `true | false | null` — Linux reports `null` ("cannot answer") rather than a
   `false` that would claim a check nobody performed.

Also measured: querying by **serial number** exits 0 even for a present certificate, so the probe must
use the SHA-1 thumbprint.

## Three states that must not be conflated

`generated:false` (no CA) vs `generated:true, fingerprint:null` (**file exists, is not a
certificate** — the corrupt-CA state, now reportable where it used to be invisible); and
`verified:undefined` vs `verified:false`. `getCertStatus`'s key set is asserted to be exactly
`["fingerprint","generated"]`.

## Deliberate deviations, each recorded in three places

- **No `certBlobId`/`keyBlobId`**, although §6.1 sketches them: the blob store is transient
  (`BLOB_TTL_MS` 1 h) and the CA is durable with a ten-year validity. The proxy also needs a real path.
- **The import-validation gap is closed at *status* time, not import time.** Rejecting bad bytes at
  import would narrow a contract that deliberately preserves arbitrary bytes (asserted, including a
  non-ASCII payload) — a second unrequested behaviour change.
- **`tls:installCA` stays in `clientHandlers.ts`**, not `tlsHandlers.ts`: it is CLIENT-classified and
  `tlsHandlers.ts` is now pure client-delegating.

P3 is closed bar its P7-deferred UI half, so the next item on the critical path is **P4 (transport)**.
`plan/05`'s own "How to start" #1 is: *define `Transport`, implement `in-process`, and stand up the
conformance-suite skeleton* — the fastest possible feedback loop, and the one that forces the interface
to be right before I/O complicates it. That is what landed.

## What was built

- `packages/engine/src/transport/types.ts` — `Transport` (`request`/`subscribe`/`close`), `EngineEvent`,
  and the bus-name ↔ wire-name bridge.
- `packages/engine/src/transport/inProcess.ts` — `createInProcessTransport(registry, opts?)`, dispatching
  straight into `CommandRegistry.invoke()`. No `ipcMain` anywhere on the path.
- `packages/engine/src/transport/index.ts` — barrel plus a table of which of the four transports exist.
- `packages/engine/tests/conformance/protocol.conformance.ts` + `run-in-process.test.ts` — the shared
  suite and its first runner. The runner has **no assertions of its own**, by design: `plan/05` lists
  "conformance suite written per-transport instead of shared" as a risk, and a runner that grew its own
  cases would be that risk materialising.
- Exported from the engine's **public** API, above the provisional divider — the transport is what
  P5/P7/P8/P9 all speak, so it is not a P6 shim.

## Two decisions to not re-litigate

1. **`request()` resolves with a handler's value *uninspected*.** The P0 spike established that a
   handler which *resolves* — with any shape, including `{ok:false, error}` — is an envelope-level
   **success**. Most legacy handlers report failures that way and the renderer branches on them, so a
   transport that converted `{ok:false}` into a rejection would break `window.api` for every one of
   them. `request()` has exactly one failure path: the registry **threw**. The suite asserts this
   directly; it is the assertion that keeps P5 honest.
2. **Bus names and wire names are bridged in one validated place.** The bus says `log.entry`, the
   protocol says `event.log.entry`. The table is *derived* from the protocol's own `EVENT_NAMES` (not
   hand-maintained), and `assertBridgeIsTotal()` runs **at import time** — because the failure mode is a
   subscription that succeeds and never fires, which is this phase's own "works locally, broken
   remotely" class. Three engine events (`process.output`, `process.statusChange`,
   `settings.changed`) have no wire name yet; they are listed explicitly and subscribing to one is
   refused with `UNSUPPORTED` rather than accepted and silently ignored.

## Three engine-side enablers this needed

- **`CommandRegistry.invoke()` now throws `EngineError`** (`UNKNOWN_COMMAND` / `BAD_REQUEST`) instead of
  a bare `Error`. Messages unchanged, so `tests/commands/registry.test.ts:44`'s
  `toThrow(/No handler registered/)` still holds. Before this, a transport could only tell "the client
  sent a bad payload" from "the engine has a bug" by pattern-matching error text — which is exactly what
  the registry's own docstring had been inviting callers to do.
- **`EngineEventBus` and `ENGINE_EVENT_NAMES` are exported.** `EngineEvents` is a *type*, so nothing
  could enumerate it at runtime — meaning `assertBridgeIsTotal()` had nothing to validate against and
  would have passed no matter how wrong the mapping was. The class export is what lets a test build an
  **isolated** bus, which matters because the `bus` singleton is process-wide and Vitest shares a module
  registry across files in a worker.
- **`packages/engine/tsconfig.json` now includes `tests/**/*.ts`.** Neither it (`src/**/*.ts`) nor the
  root tsconfig (`src/**/*`) covered `packages/engine/tests/**` — the same unchecked-tests gap that let a
  missed `filePath` call site through in P3 item 2. **Verified with a negative control**: a deliberate
  `TS2322` in that directory is reported, so the green run means something.

The suite imports its siblings **relatively** (`../../src/…`) rather than via `@bifurc/engine/*`, because
the package's `exports` map wildcards to `./dist/*.d.ts` — the specifier would have typechecked the suite
against **build output**, which is the stale-`dist` failure mode `vitest.config.ts` already documents.

## The finding that matters for step 3

**The suite's `subscribe()` cases assert synchronously**, with no `await` after `bus.emitTyped(...)`.
That holds for `in-process` and — **measured, not assumed** — for `PassThrough`, which in flowing mode
emits `data` synchronously from `write()`:

```
MEASUREMENT  delivery immediately after emitTyped: 1; after settle: 1
```

**A TCP socket is never synchronous**, so the `ws` runner (step 3) must make those cases await a
delivery barrier (`vi.waitFor` for positives, a bounded settle for negatives). Real suite defect,
exposed by transport #2, owned by transport #3 — deliberately not fixed here, because rewriting the
programme's most valuable test asset unverified is worse than the defect.

## Three bugs found by executing it (all invisible to `tsc`)

1. **`framing.ts` retained its buffer after a fatal error.** 4 bytes for an oversized header, but up to
   `MAX_FRAME_BYTES` for a rejected `invalid_json` body — and the decoder is owned by the session and
   outlives the stream. Fixed: all three failure sites now go through one `fail()` that releases it.
2. **`close()` left the *server's* bus listeners attached.** Invisible in spawn mode (the pipe ends and
   the engine cleans up), but an **attached** transport must not end a pipe it does not own, so the
   engine accumulated a listener per closed session. Fixed: a graceful close sends `unsubscribe` for
   every live name first.
3. **A server-side fatal error never told the client**, which then waited forever — the classic stdio
   hang, invisible until something crashes. Fixed: `fail()` **ends the output**, while a graceful
   `close()` deliberately does not (the output is usually `process.stdout`).

## `stdio` design points worth not re-litigating

- It carries the **frozen `@bifurc/protocol` envelopes** (`RpcRequest` / `RpcResponse` / `EventEnvelope`),
  discriminated by which key is present — not a stdio-specific envelope, or `ws` needs a translation layer.
  A serialising transport has **two `ok` flags that are not the same flag**: `{ok:true, data:{ok:false}}`
  is a success whose value rides through as data; `{ok:false, error}` is a throw and rejects.
- Transport control uses **reserved bare action names** (`subscribe` / `unsubscribe`); `stdio.ts`
  **throws at import time** if the protocol ever gains a command with one of those names.
- The server is deliberately **not** a `Transport` — `request()` means "invoke this", and a server
  receives requests rather than making them.
- No `hello`, no auth, no replay, no coalescing, no per-command timeout. Items 3–5.

## P4 — the synchronous-delivery defect is now FIXED (supersedes the note above)

The section above says the suite's synchronous-delivery assumption is "deliberately not fixed here".
**That is superseded: it is fixed, and verified by a negative control.** Same day, later.

**What was wrong.** The `subscribe()` cases asserted immediately after `emitTyped()` with no `await`.
That passes for `in-process` (direct call) and for `PassThrough` (flowing mode emits `data` from
`write()`), so the suite silently required **synchronous delivery** — an implementation detail of the
only two transports that existed, and something the `Transport` interface never promised. A TCP socket
cannot behave that way, so `run-ws.test.ts` would have failed for a reason that is not a defect in `ws`.

**The fix — `deliver()` in `protocol.conformance.ts`.** It emits a **sentinel** on
`event.entity.changed` (a channel no case uses as its *subject*) and waits for that to arrive:

```ts
async function deliver(transport: Transport, bus: EngineEventBus): Promise<void> {
  const arrived: EngineEvent[] = [];
  transport.subscribe([SENTINEL_EVENT], (e) => arrived.push(e));
  bus.emitTyped("entity.changed", { wsId: "sentinel", kind: "sentinel", action: "updated" });
  await vi.waitFor(() => expect(arrived).toHaveLength(1));
}
```

Delivery is FIFO within a session, so the sentinel arriving proves everything emitted before it was
already delivered — and in the negative cases proves the event was *skipped* rather than merely slow.
No sleep and no polling for the event under test: **a `setTimeout(0)` would not do**, because a socket's
bytes can take several ticks and a timeout that is *usually* long enough is a flaky test. The sentinel
takes its own `seq`, but only its own subscription sees it, so a case asserting `[1,2,3]` is unaffected.
Seven cases now await it (8 call sites — the unsubscribe case uses it twice).

**The negative control — `tests/conformance/run-deferred-delivery.test.ts`.** A test double wrapping
`createInProcessTransport` so every event callback is deferred one **macrotask** (`setImmediate`, not
`queueMicrotask` — a microtask is too close to synchronous to prove anything). It supplies the one
property that distinguishes the situations without a socket, port or auth handshake.

**Teeth check (the important part).** Neutering `deliver()` and re-running fails **exactly 6 cases, all
on the deferred runner** — `Test Files 1 failed | 2 passed (3)` — while `in-process` and `stdio` stay
green. So the barrier is load-bearing *and* is not papering over anything. Note the one *negative* case
("does not deliver an event the caller did not subscribe to") passes either way: **a removed barrier
cannot fail a `toHaveLength(0)` assertion** — which is exactly why the barrier matters there. Without it
that case is not wrong, it is *vacuous*.

Delete `run-deferred-delivery.test.ts` once `run-ws.test.ts` exists — then the real transport is the
control.

**Also in this turn:** the every-command matrix went from a **sample of one command to a sweep of 92**
(all of `COMMAND_FIXTURES`' 93 minus the reserved `config.get`), asserting two things per command per
transport — valid payload resolves, near-miss invalid payload rejects `BAD_REQUEST`. The invalid half is

Zod schema ran on the far side of the transport** (a `null` payload would pass for unrelated reasons).

## P4 item 4 — auth, as a decorator, so the `ws` gate became satisfiable

**`packages/engine/src/transport/auth/{scopes,token,authenticated,index}.ts`.** The decision that
matters: it is a **decorator** (`createAuthenticatedTransport(inner, opts)`), not a feature of each
transport. `ws` is gated on this item, and a gate that can only be satisfied by building the thing it
gates is not a gate — a decorator is testable over `in-process` today, so the handshake, the token
check and the scope gate are built and proven **before the socket exists**. `in-process` and `stdio`
are never wrapped (`stdio` needs none — "the pipe is inherited and process-scoped"; `in-process` has
no boundary).

**Scope table: 93 explicit lines, total, fail-closed.** `assertScopesAreTotal()` throws **at import**
if the table and `COMMANDS` disagree either way — so a protocol addition cannot produce an
accidentally ungated command; the engine refuses to load until someone assigns a scope.
`requiredScopeFor()` returns `undefined` (not a default), `commandIsAllowed()` then returns **false**.
Explicit rather than regex, same reasoning as `COMMAND_FIXTURES`: this gates `tls.*`, `server.*` and
every `*.execute`. **No implicit hierarchy** — `admin` does not imply `read`; scopes are an explicit
set so "what can this session reach?" is a lookup, not a derivation. Presets:
`SHELL_SCOPES` (all) / `COMPANION_SCOPES` (`read`+`write`) / `READ_ONLY_SCOPES`.

**Three plan/reality mismatches found while writing it** (the plan's table is intent; the file is the
resolution): (1) plan says `applications.*`, real namespace is `application.*`; (2) plan says
`runner.*` → `execute` but **no runner-execution command exists** (the six are `getHistory`/
`listFolderIds` read + `saveReport`/`exportReport`/`saveConfig`/`loadConfig` write); (3) `*.list` →
read **overlaps** `applications.*` → admin on `application.list` — resolved by the narrower rule
(pure reads inside an admin namespace are reads).

**Token** (`token.ts`): `ensureEngineToken()` **rotates on every call** — a token surviving a restart
is a credential surviving a restart. `BIFURC_ENGINE_TOKEN` supplies it out of band (Docker/mounted
secret) and writes **no file**; an empty env var falls through to generation. `verifyToken()` uses
`crypto.timingSafeEqual`, **not `===`** (a string compare short-circuits at the first differing byte,
leaking how many leading bytes were right — theoretical over loopback, the entire point remotely).
`timingSafeEqual` **throws** on length mismatch, so lengths are compared first. `0600` at creation +
`chmod` for overwrite, **but on Windows neither does anything** (no POSIX bits; `mode` maps to the
read-only attribute only) — the data dir ACL is the whole protection. Assigned to P9/P12.

**Four failure modes, deliberately not one code:** wrong/missing token → `UNAUTHORIZED` + **closes**;
**major** version mismatch → `UNSUPPORTED` + closes; scope the session lacks → `FORBIDDEN` + **stays
open** (identity was proven; closing would make a mis-scoped client look like a network fault);
malformed `hello` → `BAD_REQUEST` + stays open (it claimed nothing to revoke). A non-string `token`
is `BAD_REQUEST` (fails the schema), not `UNAUTHORIZED`.

**Version check is `checkVersionCompatibility()`, never `!==`** — a naive equality check would refuse
the companion extension, which the protocol's own comment calls the *expected* state for weeks after
every release. Only a major mismatch is refused. There is a conformance case for the minor-mismatch
path specifically, because that is what a "simplify to `!==`" refactor would break.

**The gate runs BEFORE payload validation**, so a forbidden command is refused identically whether or
not its payload is well-formed. Reversed, the *shape* of the error would tell an unauthorised caller
whether a command exists and what its schema wants — a free protocol-mapping oracle.
